# Operating instructions

This repo holds the working setup for a solo apartment locator business in Austin, Texas. It is a business system, not a software project.

**This repository is public.** Do not commit income figures, health details, personal history, relationship details, client names, or anything else that would not be fine on a billboard. Private context belongs in `context.local.md`, which is gitignored and never committed.

## The skills

| Skill | Use it when |
| --- | --- |
| `focus` | Stuck, spinning, overthinking, or unsure what to do right now. The daily driver. |
| `one-person-business` | Deciding what to build, whether an idea is worth it, or which income stream deserves focus. |
| `life-reset` | A full reset. Vision, goals, routine, first week. Run it quarterly, not weekly. |
| `notes` | Make this chat keep track of what it did and what it noticed. Say "give me the artifact" to see it. |

`apartment-marketplace-ads` handles ad creation and lives in the personal skills directory.

## How to work here

**Default to action over planning.** The failure mode in this business is not laziness, it is over-preparation. Building a system is how avoiding a client conversation disguises itself as productivity. When asked to build tooling, first check whether an unblocked revenue action exists, name it, and only build if the answer is still yes.

**Revenue comes from signed leases, and leases come from conversations.** Any work that does not eventually produce a message to a prospective renter is support work. Support work is fine, but it never goes first.

**Count actions, not intentions.** Progress is measured in leases signed and people contacted. Not hours, not plans, not tools built. Logging happens in real time, never from end-of-day memory.

**Say hard things plainly.** Weak ideas get flagged, unrealistic timelines get named, avoidance gets called out once and without moralizing. Encouragement that papers over a real problem costs money.

**Be brief.** Long responses become another thing to read instead of another thing done.

**Log every completed thing, immediately.** Append one line to `worklog.local.md` the moment something is finished, under today's date, newest date at the top. Format is `- [chat name] what was done, in one line`. Append only, never rewrite or condense earlier lines. This file is the single record across every chat, so keep entries factual and short: what was done, not how it went. No adjectives, no self-assessment, no progress narration.

**One chat, one job.** Each chat in the fleet owns a single job, listed in `chats.md`. When asked for something another chat owns, name that chat and decline the work rather than absorbing it.

## Constraints

- Cloud sessions cannot reach a local browser, so anything requiring a logged-in Chrome must be done by hand or in a session with the browser extension attached.
- Facebook Marketplace posting is manual on purpose. Automated posting risks account restriction, and the account is the lead pipeline.
- Real estate work here is Texas licensed. Keep public-facing copy TREC compliant.
